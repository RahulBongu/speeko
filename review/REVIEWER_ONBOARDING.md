# Speeko — Native-speaker review onboarding

This guide is for qualified native speakers reviewing the Speeko draft curriculum.
The review package is generated by `node scripts/export-review.mjs` from
`content/dist/*.json` (the exact artifacts the app and tests verify).

## What you are reviewing

- **315 exercises** across 10 locales: bn, gu, hi, kn, ml, mr, or, pa, ta, te.
- Kinds: `chooseMeaning` (221), `typeTranslation` (65), `matchPairs` (20),
  `listenChoose` (9, synthetic audio on all 9).
- Every item ships `reviewStatus: "automated_reviewed"`, which is not human approval. Nothing is certified yet.

## Review rubric

For each exercise, judge these dimensions and note any failure:

1. **Meaning accuracy** — does the prompt's intended meaning match the answer?
2. **Grammar** — is the target-language sentence grammatically correct?
3. **Register / formality** — is the tone appropriate for a beginner lesson?
4. **Script and transliteration** — correct native script, consistent romanization?
5. **Vocabulary consistency** — same word spelled the same way across lessons?
6. **Learning objective** — does the item test what the lesson claims?
7. **Difficulty** — appropriate for the stated level (A1/A2)?
8. **Ambiguity** — is there exactly one defensible answer?
9. **Audio** — for `listenChoose`, is the (missing) audio appropriate? (mark `revise` if audio is required but absent)

## Decision values

- `keep` — item is correct as written; no changes needed.
- `revise` — item has an error; describe the fix in `reviewNotes`.
- `remove` — item should not ship; explain why in `reviewNotes`.

## Marking uncertainty

- Leave `reviewDecision` blank if you did not check an item. Blank is not an approval.
- Use `reviewNotes` to record "unsure", "needs second reviewer", or "dialect-dependent".
- If a word has multiple accepted spellings, note both and mark `keep` with a note.

## How to record approvals

1. Open `review/review-<locale>.csv` (one row per exercise, in path order).
2. Fill `reviewDecision`, `reviewNotes`, and `reviewer` (your name or handle).
3. Return the CSV (or a diff) to the project owner. **Nobody else marks items reviewed.**
4. The owner applies decisions, flips reviewed lessons to `reviewStatus: "reviewed"`
   with `reviewer: "<name>"`, and re-runs `pnpm sync:content`.
5. The owner runs `node scripts/import-review.mjs` to validate the returned CSVs
   against the current package (item IDs, versions, required fields).

## Rules

- An AI-assisted review is **not** a native-speaker certification.
- Do not approve an item you did not personally check.
- Do not change the item ID or version; the import validator rejects stale approvals.
- `listenChoose` items ship with an empty `audioUrl`; mark them `revise` if audio is required, or `keep` if the text alone is acceptable for the alpha.

## Contact

Return completed CSVs to the project owner. Questions about scope or rubric go to the owner before submission.
